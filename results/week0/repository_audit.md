# Repository Audit: Week 0 Preparation

**Date:** October 2026  
**Context:** Research repository built around SARA (*Selective and Adaptive Retrieval-Augmented Generation with Context Compression*), Mistral-7B, QASPER, BM25 retrieval, and SFR-based soft compression.  
**Objective:** Audit existing repository components before implementing **Week 0: Dataset + RAG Evidence Understanding / Motivation Study**.

---

## 1. Executive Summary

This repository implements the SARA architecture and contains downstream research extending SARA with Query-Conditioned Context Allocation (QCCA). SARA represents retrieved evidence as a hybrid mix of $k$ full-text passages and $n - k$ soft-compressed retrieval embeddings injected at `<COMPRESS>` token positions via a trained projection layer into Mistral-7B-Instruct-v0.2.

Downstream weeks (Weeks 1 through 5) have explored fixed-budget sweeps, oracle headroom analysis, feature discovery over 64 pre-generation observable features, diagnostic error analysis, and nonlinear stage-2 modeling.

Week 0 logically precedes those weeks by establishing the foundational empirical and mechanistic motivation:
1. Understanding the QA and evidence structure of QASPER.
2. Understanding how Mistral interacts with retrieved evidence across transformer layers.
3. Diagnosing whether Mistral uses retrieved passages uniformly (via attention mass, intervention ablation, and concentration metrics).
4. Connecting these observations directly to SARA's parameter $k$ to motivate adaptive allocation.

This audit catalogues all existing reusable assets, identifies what Week 0 must implement, and defines key architectural and scientific guardrails.

## 2. Reusable Components Found

### 2.1 Dataset Splits and Manifests
- **Split Manifest (`Baselines/SARA-main/data/manifests/qasper_split.json`):**
  - Defines the official paper-disjoint train/dev split created by `make_qasper_splits.py` (seed 42, dev fraction 0.1).
  - Papers: 858 total, 772 train papers, 86 dev papers.
  - Rows: 2,088 train rows, 231 dev rows, 1,309 test rows.
  - Paper disjointness: Train and dev paper sets have zero overlap (`overlap_train_dev: []`).
- **Reformatted JSONL Files (`Baselines/SARA-main/data/reformatted/`):**
  - `QASPER_train_split.jsonl`: 2,088 queries with paper IDs (`example_id`), questions, BM25-ranked full-paper paragraph contexts, and answers.
  - `QASPER_dev.jsonl`: 231 queries matching the exact development cohort used in Weeks 2–5.
  - `QASPER_train.jsonl`: Full training set (2,319 queries).
  - `QASPER_test.jsonl`: Official test split (1,309 queries) — **FROZEN**, will not be accessed or evaluated for development.
- **Raw QASPER Arrow Cache (`~/.cache/huggingface/datasets/allenai___qasper/`):**
  - Contains complete original paper text hierarchy (`title`, `abstract`, `section_name`, `paragraphs`) and fine-grained annotation structures:
    - Multiple annotator answers per question.
    - Gold evidence paragraph strings (`evidence`).
    - Exact highlighted evidence spans (`highlighted_evidence`).
    - Answer categories: `unanswerable`, `extractive_spans`, `yes_no`, `free_form_answer`.
  - Accessible offline via `datasets.Dataset.from_file` without network calls.

### 2.2 Precomputed Retrieval & Embedding Artifacts
- **Development Retrieval Matrix (`results/week2/raw/dev_retrieval.jsonl`):**
  - 231 dev queries with top-10 BM25 retrieved passages, including passage IDs, ranks 1..10, BM25 scores, and full passage text.
- **SFR Embedding Cache (`results/week2/raw/dev_sfr_embeddings.pt`):**
  - PyTorch dictionary caching 4096-dimensional normalized embeddings for each of the top-10 retrieved passages across all 231 dev queries, generated by `Salesforce/SFR-Embedding-Mistral`.
- **Precomputed Retrieval Features (`results/week2/processed/dev_retrieval_features.jsonl`):**
  - Pre-generation features: $\rho_1$ (top-1 concentration), $\Delta_{12}$ (top-1/top-2 margin), normalized entropy $H_{\text{norm}}$, query token length, and high-scoring passage count $N_{\text{high}}$.

### 2.3 Model & Checkpoint Loading Infrastructure
- **Model Loader (`Baselines/SARA-main/src/model/loader.py`):**
  - `load_sara_for_eval(adapter_dir, device, dtype)`:
    - Loads base `mistralai/Mistral-7B-Instruct-v0.2`.
    - Extends tokenizer with `<pad>` (32000) and `<COMPRESS>` (32001).
    - Attaches LoRA adapter (`peft`).
    - Injects SARA projection layer from `sara_extras.safetensors` via `load_sara_extras`.
- **SARA Architecture (`Baselines/SARA-main/src/model/xMistral/`):**
  - `XMistralForCausalLM`: Custom causal language model that intercepts input embeddings and replaces `<COMPRESS>` token positions with projected soft-retrieval embeddings.
- **Trained Checkpoints (`Baselines/SARA-main/checkpoints/finetune/`):**
  - `sara_qasper_proj_lr5e4_seed42`: Trained SARA LoRA + projector checkpoint.
  - `rag_qasper_lora_r16_seed42`: Trained Standard RAG LoRA checkpoint.

### 2.4 Prompt Construction & QA Metrics
- **Prompt Builders (`src/week2/sweep_runner.py` & `Baselines/SARA-main/src/model/prompt_builder.py`):**
  - `build_evaluation_prompt(question, passages, k, tokenizer)`:
    - Formats top-$k$ passages as natural language text in `## Context`.
    - Formats ranks $k+1 \dots 10$ as `<COMPRESS>` tokens in `## Additional Context`.
    - Appends `## Your Task`, Question, and Mistral `<s>[INST] ... [/INST]` chat formatting.
- **Evaluation Utilities (`src.metrics.metrics` & `src/week2/sweep_runner.py`):**
  - `compute_qa_metrics`: Max-reduction token $F_1$, exact match (EM), and ROUGE-L over multiple gold references.

### 2.5 Feature Engineering & Analysis Library
- **Pre-generation Feature Library (`src/week4/feature_discovery.py`):**
  - Implements lexical tokenization, stopword filtering, conjunction/comparison regexes, question word classification, lexical coverage, and embedding similarity utilities.

## 4. Missing Components That Week 0 Needs to Implement

1. **Modular `DatasetAdapter` Interface (`src/week0/dataset_adapter.py`):**
   - Abstract base class with methods: `load_split`, `get_query`, `get_document`, `get_gold_answer`, `get_gold_evidence`, `get_metadata`.
   - Concrete `QASPERAdapter` implementing these methods by linking the SARA reformatted records with the raw paper arrow records.
2. **Dataset & Evidence Characterization Engine (`src/week0/dataset_analyzer.py`):**
   - Multi-level statistics:
     - Paper-level: document length distribution, section counts, paragraphs per section.
     - Question-level: length, observable query characteristics (WH-type, numerical, comparison, multi-part/conjunction, lexical diversity).
     - Answer-level: length, answer types (unanswerable, yes/no, extractive, abstractive/free-form).
     - Evidence-level: gold evidence count, span lengths, document location (relative depth), dispersion across sections, redundancy.
     - Retrieval-level: gold evidence recall@k, rank of first gold passage, score decay, top-1/top-2 margin, score entropy.
   - Separate execution on TRAIN and DEV splits.
3. **Mistral Layer / Hidden-State Analyzer (`src/week0/layer_analyzer.py`):**
   - Controlled stratified sample of DEV questions (30–50 examples).
   - Hook-based / forward-pass hidden-state extraction at designated layers:
     - Embedding / Layer 0
     - Early layers (e.g., Layer 4, 8)
     - Middle layers (e.g., Layer 16)
     - Late layers (e.g., Layer 24)
     - Final layer (Layer 31 / output norm)
   - Token-span extraction: Query span vs. Passage 1..10 spans.
   - Mean-pooling / normalized representations per passage and query.
   - Layer-wise cosine similarity tracking:
     - Query $\leftrightarrow$ Passage similarity by layer.
     - Evidence vs. non-evidence passage similarity.
     - Pairwise passage separation.
   - PCA dimensionality visualization across layers.
4. **Passage Utilization & Attention Diagnostic Engine (`src/week0/evidence_utilization.py`):**
   - **Causal Attention Diagnostics:**
     - Must respect causal decoder-only prompt ordering: In SARA, passages precede the question and answer prompt (`## Context ... ## Your Task ... Question: ... Your Answer:`).
     - Question tokens and generated answer tokens can attend back to passage tokens.
     - Passage tokens *cannot* attend forward to question tokens.
     - Metric: Aggregated attention mass from generation / question tokens to each passage span, averaged across heads and length-normalized.
   - **Intervention / Ablation Diagnostics:**
     - Teacher-forced log-likelihood intervention:
       $$\text{Importance}(D_i) = \log P(\text{gold answer} \mid q, \text{all passages}) - \log P(\text{gold answer} \mid q, \text{passages} \setminus \{D_i\})$$
     - Answer generation / token $F_1$ drop under leave-one-out passage removal.
   - **Utilization Concentration Metrics:**
     - Normalized entropy: $H = -\sum p_i \log p_i / \log(n)$
     - Gini coefficient of passage utilization.
     - Top-1 and top-3 utilization share.
     - Effective number of utilized passages: $N_{\text{eff}} = \exp\left(-\sum p_i \log p_i\right)$.
   - **Signal Correlation:**
     - Cross-correlation between BM25 score, embedding similarity, attention mass, ablation importance, and gold evidence annotation.
5. **SARA Motivation & Synthesis (`results/week0/sara_motivation/week0_synthesis.md`):**
   - Grounded conceptual analysis connecting heterogeneous evidence needs and non-uniform passage utilization to SARA's parameter $k$ (high-fidelity text vs. compressed embedding).
6. **Unified Configuration (`configs/week0/week0.yaml`):**
   - Paths, random seeds, sample sizes, selected layers, device/dtype configurations.
7. **Comprehensive Unit Tests (`tests/week0/`):**
   - Fast, mock-based tests for adapters, query statistics, evidence metrics, attention aggregation, entropy/Gini, and output schemas without loading the 7B model.

## 5. Assumptions

1. **Document-Level Disjointness:** All development analyses rely strictly on the 86 held-out dev papers (231 queries) and 772 training papers (2,088 queries) established in `qasper_split.json`.
2. **Frozen Test Set:** `QASPER_test.jsonl` contains 1,309 queries and must remain completely untouched during Week 0.
3. **Causal Prompt Structure:** In Mistral-7B, attention is causal (strictly lower-triangular). Any valid attention diagnostic of passage utilization must measure the attention paid by subsequent tokens (question and/or generated answer tokens) to the tokens of passage $D_i$.
4. **Hardware Constraints:** The TITAN RTX has 24 GB of VRAM, with ~7 GB currently active in another process. Full attention tensors for long sequences (2,000+ tokens) across 32 layers and 32 heads require over 8 GB per forward pass if retained. Therefore, attention extraction must run one example at a time, extract on selected layers, immediately pool into passage-level statistics, and call `gc.collect()` and `torch.cuda.empty_cache()`.

## 6. Compatibility Risks & Mitigation

| Risk | Description | Mitigation Strategy |
|---|---|---|
| **GPU Memory Pressure** | Loading Mistral-7B-Instruct (14 GB in bf16) alongside existing background processes could trigger CUDA OOM if large attention tensors are allocated. | Use `torch.inference_mode()`, process single queries (batch size 1), evaluate attention on 5 representative layers, and accumulate summary statistics immediately rather than storing raw tensors. |
| **Causal Attention Invalidity** | Interpreting prompt token attention as bidirectional would produce invalid zero attention from prompt tokens to subsequent tokens. | Measure attention from question tokens and/or generated answer tokens back to passage tokens, clearly documenting the token coordinate ranges. |
| **Overwriting Downstream Results** | Week 1–5 results exist in `results/week2`, `results/week3`, `results/week4`, `results/week5`. | Strictly isolate all Week 0 outputs inside `results/week0/`, `src/week0/`, `scripts/week0/`, `notebooks/week0/`, and `configs/week0/`. |
| **Offline HF Datasets Cache** | `datasets.load_dataset` may attempt remote validation if network access is restricted. | Use `datasets.Dataset.from_file` pointing directly at the local arrow files in `~/.cache/huggingface/datasets/allenai___qasper/`. |
