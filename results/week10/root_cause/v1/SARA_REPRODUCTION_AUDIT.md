# SARA reproduction audit

Audited official repository tree `639f5f48b86672c270046141f44a1b5eab6c8b96`; paper and retrieved-source SHA256s are in `audit/sources/sources.json` and the manifest. The crosswalk records local source evidence and ambiguities.

The official defaults are BM25, Mistral-7B-Instruct-v0.2 and SFR-Embedding-Mistral. Paper Table12 reports QASPER F1 SFR55.44/BGE44.47/BM2536.15. Section3.4 also mentions MPNet; section3.1 names bge-reranker-v2-m3. The exact BGE first-stage corpus/reranking setup is not established by those inconsistent descriptions. Do not fabricate an exact MPNet score or a BGE bi-encoder ID. [Paper](https://arxiv.org/pdf/2507.05633), [repository](https://github.com/Ahren09/SARA).

Locally SFR encodes BM25-retrieved passages and query features. W6 MiniLM selects FULL passages from that pool; W9 MiniLM also retrieves over paper-local chunks. No completed matched SFR full-paper retrieval/generation run was located. This is an inventory finding, not proof nothing was ever run outside the repository. MiniLM first appears in tracked W5 allocator code (`97657ca`); W6 router code (`2133292`) establishes its cheap frozen cosine scorer role. No prior comparison justifying it over SFR was located.

Document SFR vectors are query-agnostic. Routing can be query-conditioned while those vectors remain unchanged. Local projector dimensions and public backbone match the architecture; equivalence to the paper's trained weights is unproven. Current official README simplifies inference to two methods, while the paper describes refinement. Local W6 restores BM25 order after selection. Current upstream `rank_documents` has an inconsistent list-to-Document branch differing from local code; this snapshot was inspected, not executed. W10 records these differences rather than rewriting history.

SeleCom provides [official code](https://github.com/yhliu7458/SeleCom) and [released weights](https://huggingface.co/Ryan7458/Selecom). It uses a query-conditioned 0.6B selector, projector and adapted generator; p8 selector positions yield n2 generator latents. Generator utilization training is part of the mechanism, not an optional drop-in assumption. Mistral7B/Qwen2.5-7B pipelines accept question/answer/documents JSONL, making QASPER-format adaptation plausible without recreating the synthetic corpus. Nominal FP16 weights fit24GB, but its FlashAttention2 setup needs a Turing port and representative peak-memory test. No faithful evaluation is claimed. QCS256 is a distinct textual surrogate. [Paper](https://arxiv.org/html/2602.15856v1).

ACC-RAG constructs ordered latent prefixes at multiple granularities; reconstruction/continuation and teacher KL train the compressor with frozen decoder. Its sufficient/continue selector uses decoder states and trajectory policy gradient, rather than direct global-k classification. Labels still derive from counterfactual answer evaluations, so label noise remains relevant. Released checkpoints were not located from its official paper. Training costs are substantial and paper hardware times cannot be transferred to TITAN. [Published paper](https://aclanthology.org/2025.findings-emnlp.1307/).

SPARKLE uses a3B proxy, structured knowledge state and PPO tree rollouts, with reward combining evidence recall and answer F1; retriever/reader form the environment. Its E5/Qwen2.5 setting and transfer experiments do not establish a fix for SARA representation loss. Full PPO adds generation cost; defer until upstream controls finish. [Paper](https://aclanthology.org/2026.acl-long.1793/), [code](https://github.com/jyfang6/sparkle).

SANE's wide dense retrieval, synopsis LM selection, blueprint extraction and evidence-only reader differ from W9's local generators, retained SARA context and structured validation. W9 results characterize inspired variants, not a faithful negative reproduction. [Source](https://arxiv.org/html/2608.00658v1), [code](https://github.com/JamyDon/SANE).

Cache reuse: old W2/W5 vectors cover BM25 top10 and historical precision, not automatically the full W10 candidate corpus. Old D0 is a SARA k4 draft, not a no-evidence baseline. W10 must verify text/order/model/precision/config identity before claiming reuse; this first pass does not reclassify those artifacts or regenerate them. R FULL intentionally uses the same trained local reader as R SARA to isolate representation, rather than the separately trained official Standard RAG adapter.

NEST naming: the matrix uses Nested Evidence Survival (ACL industry2026). Nearest Neighbor Speculative Decoding (NeurIPS2024) is a different NEST mechanism; neither has been implemented here. This ambiguity is not evidence that either is a new adaptive-controller baseline. [Earlier NEST](https://arxiv.org/abs/2405.19325).
